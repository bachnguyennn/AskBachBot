GRAMMARME ON-DEVICE WRITING ASSISTANT PROJECT — BACH NGUYEN

GRAMMARME PROJECT: OVERVIEW
Year: 2026 (November). Domain: developer tools / on-device NLP / browser software. Tools: TypeScript, React, Vite, Harper (open-source grammar engine) compiled to WebAssembly, Chrome Extension Manifest V3, Vitest. GitHub: github.com/bachnguyennn/GrammarMe. Live site: bachnguyennn.github.io/GrammarMe, with the web editor at bachnguyennn.github.io/GrammarMe/editor. Write-up: bachnguyennn.github.io/projects/grammarme.
GrammarMe is a free, private, Grammarly-style writing assistant built solo by Bach. It underlines spelling, grammar and punctuation mistakes as you type, explains each one, and fixes it in one click. It comes as a web editor and a Chrome extension for text boxes on websites, including rich-text editors such as Gmail. Bach built everything around the Harper engine: the editor, the extension, the suggestion logic, the evaluation, and an optional ChatGPT check.

GRAMMARME PROJECT: THE PROBLEM AND DESIGN GOALS
Most writing assistants send what you type to a server, and the good ones need a subscription. Bach set three hard limits for GrammarMe: text stays on the device by default, it costs $0 to run, and it stays light enough for an 8 GB laptop. A local rule engine cannot catch everything, so AI is available for the gaps, but it stays off until the user asks for it.

GRAMMARME PROJECT: ARCHITECTURE
- Shared core: one TypeScript package holds the suggestion contract, the edit helpers, the Harper adapter, and the AI prompts and guards. The editor and the extension both build on it.
- Web editor: React and Vite, with Harper in a Web Worker so loading the 20 MB WASM file never stalls typing. Checks run after a 300 ms debounce, and underlines shift instantly on each keystroke with no network.
- Chrome extension: one Harper instance runs in an offscreen document and all tabs share it, instead of loading a copy per tab.
- Optional AI: off by default and sent only on request. The extension can use the user's own ChatGPT Plus or Pro plan through a small local companion program, with no API key.

GRAMMARME PROJECT: IMPLEMENTATION DECISIONS
- Harper over LanguageTool: LanguageTool catches more, but it means either sending text to a third-party API or running a Java server that needs 1 to 2 GB of RAM. Bach accepted Harper's lower recall and left the gap to the optional AI check.
- Fixes cannot land in the wrong place: every edit bumps a document version, underlines and late results are rebased, and a fix is refused unless its version is current and the text at that position still matches.
- A plain textarea, not a rich-text framework: a native textarea sits on top of a backdrop that only draws the underlines, which gives native undo, caret behaviour and IME support for free.
- AI edits are located by quoting text: models count characters badly, so the model quotes what it wants to change and code finds that text. Missing, ambiguous or no-op edits are rejected.
- ChatGPT credentials stay on the user's computer: OpenAI's sign-in for local apps finishes on a 127.0.0.1 address, which an extension cannot receive, so a companion started by Chrome handles the sign-in and keeps the credentials in files on disk.

GRAMMARME PROJECT: EVALUATION RESULTS
Bach wrote a labeled dataset of 171 sentences: 125 with 128 known errors, and 46 correct sentences to measure false alarms. On-device results with the shipped settings, in American English, with no AI:
- Precision 84.0% (89 of 106 flags) and recall 69.5% (89 of 128 errors).
- Correct fix: 93.3% of caught errors (83 of 89) had the right top suggestion.
- False alarms: 10 of the 46 correct sentences (21.7%) were flagged at least once.
- Errors caught by category: spelling 30 of 30, articles 15 of 15, word choice 16 of 22, punctuation 10 of 16, tense 8 of 14, subject-verb agreement 10 of 19, wordiness 0 of 12.
- Speed: about 1.2 ms per sentence and about 49 ms for a 1,196-word document, measured in Node on an Apple M1 Pro, not in a browser.
Before tuning, precision was 78.8% and 30.4% of correct sentences were flagged. The evaluation showed one rule suggesting "a dress" for "adress" and another hiding every other error inside long sentences. Turning off three rules and skipping spell-check on code-like words and acronyms brought those to 84.0% and 21.7%.

GRAMMARME PROJECT: LIMITATIONS
Bach documents the limits openly. The dataset is small and he wrote it, so the numbers show how settings compare, not how the checker does on real writing. There is no side-by-side comparison with Grammarly, and AI suggestion quality is not measured yet. Without AI, about 3 in 10 errors in the dataset go unflagged, including agreement errors with a longer subject and tense that depends on context.
The Chrome extension is a prototype: it installs by hand in Developer mode, works on desktop only, and does not support Google Docs. It is not on the Chrome Web Store. The ChatGPT route needs the companion on macOS or Linux and a Plus or Pro plan. When optional AI is used, text leaves the device: it goes to OpenAI with the user's ChatGPT plan.

GRAMMARME PROJECT: QUICK FACTS (FOR COMMON QUESTIONS)
- Is GrammarMe free? Yes. It costs $0 to run, with no subscriptions or paid APIs.
- Does GrammarMe send my text anywhere? Not by default. Spelling and grammar checks run in the browser, and text is sent only if the user turns on optional AI and requests a check.
- Does GrammarMe work in Gmail? Yes, through the Chrome extension. It does not support Google Docs.
- What engine does GrammarMe use? Harper, an open-source grammar checker compiled to WebAssembly.
- What did Bach learn from GrammarMe? Measure before picking defaults, decide where each kind of check should run, and treat user text as the thing that must never break.
